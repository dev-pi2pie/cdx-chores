## What's Changed

### Interactive Markdown PDF

- Added guided Markdown PDF rendering through Interactive `md -> to-pdf`.
  - Use an existing recipe or prepare a new Profile, Template, or Project artifact.
  - Review effective settings before writing or rendering.
  - Render with a temporary recipe or save the recipe durably.
  - Recover from failures without implicitly regenerating an accepted recipe.
- Added Interactive `md -> pdf-recipes` for preparing and saving reusable recipes, with an optional handoff into the same `to-pdf` rendering flow.
- Added Interactive code-highlighting controls.
  - Profile `formal-guide` can save reusable highlighting settings.
  - Each render can use the recipe setting, enable highlighting, or disable it without modifying the recipe.

### Codex-Assisted Font Suggestions

- Added installed-font suggestions to the Codex Assistant font-hint editor.
  - Search and rank matching families from the local fontconfig inventory.
  - Accept a suggested family or retain custom input.
  - Send only the accepted, reviewed hint to Codex -- not the local font inventory.
- Preserved accepted Profile font choices across generated Template and Project bundles.
  - Generated CSS avoids silently replacing Profile-owned typography.
  - Template-owned layout and cover styling remain available.

### Markdown PDF Reliability

- Hardened generated Interactive Markdown PDF recipe lifecycles, including temporary-session cleanup, durable-save recovery, output and symlink collision checks, Codex report handling, and scoped retries.

### Compatibility and Maintenance

- Required Pandoc 2.0 or newer for `md to-pdf`; `doctor` reports the requirement.
- Codex SDK baseline for `v0.1.6`: `0.146.0`.
- Refreshed the reviewed runtime and development dependency set and adopted TypeScript 7 while preserving the Node.js `>=22.23.0` runtime contract.

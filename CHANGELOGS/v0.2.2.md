## What's Changed

### Codex Benchmark and Session Controls

- Added `codex-bench` to run the same prompt in fresh sessions across a model and requested-speed matrix or explicit `--case MODEL=SPEED` pairs. It reports first-token time, turn duration, and output tokens per second, with compact summaries, optional token usage, and JSON output. Run `doctor --details` to check benchmark readiness. [Benchmark guide](https://github.com/dev-pi2pie/cdx-chores/blob/v0.2.2/docs/guides/codex-benchmark.md)
- Supported Codex helpers, `interactive`, and `codex-bench` now accept `--codex-speed` and `--session-retention`. Request Standard, Fast, or Ultrafast, and choose whether to keep, archive, or permanently delete sessions created by the command. `codex-info models` shows the speed tiers Codex advertises. [Codex execution guide](https://github.com/dev-pi2pie/cdx-chores/blob/v0.2.2/docs/guides/codex-execution-configuration.md)

### DuckDB 2 Migration

- DuckDB-backed data commands now use DuckDB 2.0.1. Check saved queries for SQL behavior changes such as regex matching, lambda syntax, and division by zero. [Migration guide](https://github.com/dev-pi2pie/cdx-chores/blob/v0.2.2/docs/guides/data-duckdb-usage.md#duckdb-2-migration)
- Excel and SQLite inputs require extensions installed for the current engine. Run `cdx-chores data duckdb extension install excel` or `cdx-chores data duckdb extension install sqlite`. `data query --install-missing-extension` can also opt in to installation for a query.

### Markdown PDF

- Interactive and default direct rendering restrict WeasyPrint to local files and embedded data URLs, including assets loaded from stylesheets. Both modes require WeasyPrint 70.0 or newer with `--allowed-protocols` support. Use `--allow-remote-assets` with `md to-pdf` to enable remote fetching for one direct render. [WeasyPrint compatibility](https://github.com/dev-pi2pie/cdx-chores/blob/v0.2.2/docs/guides/markdown-pdf-usage.md#weasyprint-compatibility)
- Automatic titles in the built-in template use Pandoc's parsed Markdown to compare the front matter title with the first eligible H1, including underlined headings. With no cover, the metadata block stays when inline `display` or `visibility` hides matching heading text, or when an earlier H1 may still be visible. When author stylesheets apply, the CLI verifies that the matching H1 prints in full before omitting the metadata block. [Automatic metadata titles](https://github.com/dev-pi2pie/cdx-chores/blob/v0.2.2/docs/guides/markdown-pdf-usage.md#automatic-metadata-titles)
- Markdown PDF authoring suggestions better distinguish fenced code in lists and quotes from document headings and tables.

### Rename and DOCX

- `rename apply` now checks that each move that changes a path has an existing regular source file and valid endpoint directories before running any renames. [Rename plan validation](https://github.com/dev-pi2pie/cdx-chores/blob/v0.2.2/docs/guides/rename-plan-csv-schema.md#strict-replay-contract)
- DOCX title extraction rejects malformed XML such as CDATA outside the document root. Rename falls back to deterministic rules when extraction fails. [DOCX extraction behavior](https://github.com/dev-pi2pie/cdx-chores/blob/v0.2.2/docs/guides/rename-scope-and-codex-capability-guide.md#compact-capability-matrix)

### Compatibility

- The package now requires Node.js `22.23.5` or later. Use an up-to-date Node.js 22, 24, or 26 release. [Runtime guidance](https://github.com/dev-pi2pie/cdx-chores/blob/v0.2.2/README.md#quick-start)
- The Codex SDK baseline is `0.172.0`. The `doctor` benchmark readiness check expects Codex CLI 0.170.0 or newer.

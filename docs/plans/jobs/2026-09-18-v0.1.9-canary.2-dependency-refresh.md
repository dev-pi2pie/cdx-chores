## Scope

Refresh the seven reviewed dependencies for `0.1.9-canary.2`, keep the existing
Node.js runtime requirement and package-version value, and align the public
Codex SDK baseline with the tested installation.

## Updates

| Dependency | Previous | Updated |
| --- | --- | --- |
| `@duckdb/node-api` | `1.5.5-r.4` | `1.5.5-r.5` |
| `@openai/codex-sdk` | `0.154.0` | `0.155.0` |
| `mammoth` | `1.12.2` | `1.12.3` |
| `yaml` | `2.9.0` | `2.9.1` |
| `@types/node` | `26.4.1` | `26.6.1` |
| `oxfmt` | `0.67.0` | `0.68.0` |
| `oxlint` | `1.82.0` | `1.83.0` |

Runtime entries retain their existing caret-range style in `package.json`;
development-tool entries remain exact. `bun.lock` records the exact resolved
versions. The corresponding DuckDB bindings, Codex CLI/platform packages, Oxc
platform bindings, and `undici-types` changed with their direct dependencies.

## Review

- Mammoth `1.12.3` limits excessive backtracking in crafted DOCX content that
  could cause denial of service. YAML `2.9.1` limits recursive merge aliases.
- DuckDB `1.5.5-r.5` adds JavaScript-to-DuckDB value converters, data-chunk
  writing helpers, scalar-function initialization state, and appender clearing.
  It also rejects invalid integer-vector writes, mismatched chunk column counts,
  and unknown enum values. The connection and JSON result-reader implementations
  used by this repository compare unchanged between the published packages.
- The published Codex SDK JavaScript and declarations compare identically to
  `0.154.0`; its exact Codex CLI dependency advances to `0.155.0`. The adapter
  retains its lazy ESM import boundary.
- Registry metadata showed publisher continuity and npm signatures for the
  reviewed candidates. DuckDB, Codex, and Oxc packages advertised attestations.
  The published runtime tarballs were compared before installation. These
  checks support provenance review; they do not replace behavior tests.
- The lockfile diff contains the reviewed package trees and the `undici-types`
  update required by `@types/node`. The final audit reports no known
  vulnerabilities across 271 packages, and Bun reports no untrusted packages
  with install scripts.

## Documentation

- `README.md` and `docs/guides/cli-action-tool-integration-guide.md` now state
  the `v0.1.9-canary.2` / Codex SDK `0.155.0` baseline.

## Verification

- `bun install --frozen-lockfile` made no changes across 282 packages.
- Native `tsc --noEmit`, `bun run lint`, `bun run format:check`, and
  `bun run build` passed. Oxfmt found no formatting changes across 1,140 files.
  The existing TypeScript 7 experimental-API warning remains in the build.
- Node.js and Bun loaded the updated DuckDB binding and returned a simple query
  result. The installed Codex executable reported `codex-cli 0.155.0`, and the
  SDK imported successfully.
- `bun run test:all` passed: 1,246 unit cases / 4,798 assertions; 2,038
  application cases / 12,853 assertions; 2 Codex protocol cases / 68
  assertions; and 3 Pandoc cases / 138 assertions. There were no failures,
  errors, or skipped cases. The application suite used DuckDB `1.5.5`; the
  Codex suite used CLI `0.155.0`.
- Built CJS imports and CLI version checks passed under Node.js `22.22.2`,
  `24.18.0`, and `26.5.0`; the built ESM import passed under Node.js `26.5.0`.
  Node.js `22.22.2` is below the declared `>=22.23.0` runtime floor, so its
  result is supplementary rather than minimum-version verification.
- `npm pack --dry-run --json` listed 16 intended package files, including both
  module formats, declarations, README, and the executable CLI entry point.
- Final `bun outdated` reported no candidates; `git diff --check` passed.

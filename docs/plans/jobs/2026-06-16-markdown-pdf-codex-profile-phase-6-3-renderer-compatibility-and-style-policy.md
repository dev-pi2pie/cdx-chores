## Scope

Complete Phase 6.3 of the Markdown PDF Codex profile helper by fixing cover CSS that produced renderer warnings and tightening Codex profile decision facts without expanding the public CLI hint surface.

## Failure Cause

A live replay of a Codex-generated profile selected:

```yaml
cover:
  enabled: true
  style: report
pageNumbers:
  enabled: true
  position: bottom-center
  scope: body
```

Applying that profile with `md to-pdf` produced WeasyPrint warnings for `min-height: 100vh`. The warning came from deterministic cover CSS, not raw CSS generated by Codex.

The same replay also showed that Codex could infer too much report-style chrome from broad style wording. The prompt constrained patch paths and enum values, but it did not yet include reusable style policy, feature trigger rules, renderer compatibility guidance, or compact candidate traits.

## Fix

- Replaced cover-page viewport-unit sizing with paged-media-safe percentage sizing.
- Added regression coverage that enabled cover profiles no longer emit `100vh`.
- Added candidate-summary traits for cover, ToC, page numbers, code highlighting, line numbers, density, and intended use.
- Added bounded prompt facts for:
  - reusable style restraint
  - cover trigger rules
  - ToC trigger rules
  - page-number trigger rules
  - code-highlight trigger rules
  - renderer compatibility rules
- Kept the new guidance prompt-internal; no new public hint flags were added.
- Reinforced conservative page-number guidance so Codex should not enable page numbers by default for README-like documents.

## Code Review Follow-Up

The Phase 6.3 range review found three maintainability and verification risks:

- candidate trait guidance was too far from the preset source of truth
- cover sizing used percentage heights without a definite page-box height
- the cover warning regression asserted only generated CSS text instead of the render warning path

Follow-up changes:

- Moved preset guidance next to `MARKDOWN_PDF_PRESETS` so preset intent metadata stays near the preset list.
- Changed cover CSS to use a definite page height derived from normalized page size and orientation.
- Updated the profile-rendering regression runner so it emits the old WeasyPrint warning if the generated stylesheet contains `100vh`; `expectNoStderr()` now guards the warning path.

## Scope

Advance the Codex SDK baseline from `0.159.3` to `0.160.0` for the prepared
`v0.2.0-canary.4` package. Synchronize `README.md` and the CLI integration
guide, and retain historical job records.

Updated `package.json` to `^0.160.0`; `bun.lock` resolves the SDK, matching
CLI, and six platform packages at `0.160.0`. No unrelated lockfile entries
changed.

## Review rationale

- Published SDK JavaScript, source map, and declarations are identical between
  the two versions. Both downloaded SDK tarballs match npm integrity metadata.
  The import-only ESM export and Node.js `>=18` requirement are unchanged;
  the adapter retains its lazy dynamic import.
- The SDK depends on matching Codex CLI `0.160.0`. Upstream changes include
  initialization and provider-catalog fixes, requiring protocol and discovery
  verification even though the SDK wrapper is unchanged.
- Preserve the existing package and embedded CLI version `0.2.0-canary.4`,
  Node.js runtime floor, unrelated dependencies, and release-age policy.

## Verification

- Frozen installation made no further changes. Typecheck, lint, format check,
  build, and `git diff --check` passed. The build retains the existing
  TypeScript 7 experimental-API warning.
- All 31 focused Codex adapter tests passed across 8 files / 104 assertions.
  The managed isolated CLI protocol suite passed 2 cases / 70 assertions
  against Codex CLI `0.160.0`; no model-generation request was run.
- SDK thread construction and built ESM/CJS imports passed under Node.js
  `26.5.0`; the built CLI reports `0.2.0-canary.4`.
- All 8 changed Codex lockfile entries match npm integrity metadata.
  `bun audit` reports no known vulnerabilities across 269 packages, and
  `bun pm untrusted` reports no untrusted dependencies with scripts.
- `bun outdated` lists only the Shiki pair and Node types, with no eligible
  version increase under the current release-age policy.
- `bun run test:all` passed 1,593 unit, 2,269 application, 2 Codex, and
  5 Pandoc cases, with no failures, errors, or skips. Result validation,
  fixture-output validation, and cleanup completed; no results were retained.

Node.js 22 and 24 were not tested in this refresh. Registry integrity matching
does not establish a native-binary review or cryptographic provenance
verification.

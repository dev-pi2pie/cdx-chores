## Goal

Refresh the reviewed dependency set for `v0.1.8-canary.3`, preserve the Node.js
runtime contract, resolve the existing transitive XMLDOM advisory, and keep the
breaking tsdown `0.23.0` migration in a separate follow-up lane.

## Approved Package Set

- `@openai/codex-sdk`: `0.152.0` -> `0.153.0`
- `@inquirer/prompts`: `8.7.0` -> `8.7.1`
- `@inquirer/search`: `4.3.1` -> `4.3.2`
- `@types/node`: `26.4.0` -> `26.4.1`
- `oxfmt`: `0.65.0` -> `0.66.0`
- `oxlint`: `1.80.0` -> `1.81.0`
- transitive `@xmldom/xmldom`: `0.8.13` -> `0.8.15`
- deferred: `tsdown` remains at `0.22.14`; `0.23.0` requires a separate
  breaking-migration review

## Review Notes

- The Codex SDK wrapper changes only its package version and matching bundled
  Codex CLI dependency. The existing lazy ESM import and `Codex.startThread`
  adapter boundary remain compatible.
- The Inquirer patch aligns the paired prompt packages and pins their leaked
  type dependency more tightly to avoid unrelated downstream TypeScript drift.
- The Node type patch changes only the `node:ffi` pointer return declaration;
  this repository has no `node:ffi` usage.
- Oxfmt `0.66.0` contains a YAML formatting fix outside this repository's
  configured TypeScript and JSON formatting targets. Oxlint `1.81.0` focuses on
  JavaScript-plugin and Vue/Svelte fixes not enabled by this repository.
- Mammoth already permits XMLDOM `0.8.15` through its existing `^0.8.6` range,
  so the security remediation should remain a transitive lockfile refresh
  without a direct dependency or package override.

## Changes

- Updated `@openai/codex-sdk` and its bundled CLI/platform packages to
  `0.153.0`.
- Updated the paired Inquirer packages and their transitive prompt packages;
  the resolved packages now pin `@inquirer/type@4.1.1` exactly.
- Updated the exact `@types/node`, Oxfmt, and Oxlint development-tool pins.
- Updated transitive `@xmldom/xmldom` from `0.8.13` to the patched `0.8.15`
  LTS release within Mammoth's existing range. This changed only the lockfile
  resolution and did not add a direct dependency or package override.
- Updated the public Codex SDK baseline in `README.md` and
  `docs/guides/cli-action-tool-integration-guide.md` to
  `v0.1.8-canary.3` / `0.153.0`.
- Preserved package version `0.1.8-canary.3`, Node.js engine `>=22.23.0`, the
  Node-only compiler ambient-type boundary, and tsdown `0.22.14`.
- Used one-off release-age overrides for the exact reviewed package set; no
  persistent installation policy changed.

## Security Remediation

- Before the refresh, `bun audit` reported `GHSA-6gmq-8vp8-gcm6` through
  `mammoth -> @xmldom/xmldom@0.8.13`. The advisory affects XML serialization;
  the current Mammoth integration parses DOCX XML and does not invoke the
  affected serializer path.
- Mammoth `1.12.2` already permits XMLDOM `0.8.15` through its existing
  `^0.8.6` range, so the lockfile was refreshed without adding a direct
  dependency or package override. The release also hardens parser paths
  relevant to processing user-selected DOCX input.
- The final audit reported no vulnerabilities across 276 checked packages.

## Verification

- `bun install --frozen-lockfile` checked 171 installs across 287 packages and
  required no changes.
- Native `tsc --noEmit` passed with the Node-only ambient-type boundary.
- Focused prompt and path-menu coverage passed with 38 tests across 6 files.
- Focused Codex adapter coverage passed with 21 tests across 4 files. The SDK
  import smoke passed, and the bundled executable reported
  `codex-cli 0.153.0`.
- Focused DOCX/XML-path coverage passed with 24 tests across 4 files.
- Oxlint passed without diagnostics. Oxfmt checked 1,003 files without
  formatting changes.
- The Node 22-targeted build passed with tsdown `0.22.14` and TypeScript `7.0.2`
  declaration generation.
- CJS and ESM imports, the SDK import, and built CLI version smokes passed on
  Node `26.5.0` and Node `22.22.2`; the latter is slightly below the declared
  `>=22.23.0` runtime floor. The CLI reported `0.1.8-canary.3`.
- The full suite passed with 2,632 tests across 356 files and 0 failures.
- `bun audit` reported no vulnerabilities, and `bun pm untrusted` reported no
  untrusted dependencies with lifecycle scripts.
- `git diff --check` passed.
- Final `bun outdated` completed successfully and reported only
  `tsdown@0.22.14`; the starred value is age-filtered, while registry latest
  `0.23.0` remains intentionally deferred as a breaking migration.

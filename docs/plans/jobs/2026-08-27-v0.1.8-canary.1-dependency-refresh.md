## Goal

Refresh the reviewed Codex SDK, delimited-text parser, and Oxc tooling set for
`v0.1.8-canary.1` while preserving the Node.js runtime and type boundaries.

## Approved Package Set

- `@openai/codex-sdk`: `0.149.1` -> `0.150.1`
- `papaparse`: `5.6.0` -> `5.7.0`
- `oxfmt`: `0.64.0` -> `0.65.0`
- `oxlint`: `1.79.0` -> `1.80.0`
- deferred: keep `@types/node` at `25.9.5`

## Supply-Chain Review

- Compared the published Codex SDK tarballs and confirmed that the JavaScript,
  declarations, source map, README, and license payloads are unchanged. The
  package metadata advances the SDK and its bundled Codex CLI to `0.150.1`.
- Verified registry integrity, signature, publisher, and SLSA provenance
  continuity for the Codex SDK and matching Codex CLI packages.
- Verified that all six declared Codex `0.150.1` platform packages were
  published with registry signatures and provenance before installation.
- Verified PapaParse maintainer, repository, signature, and dependency
  continuity. PapaParse `5.7.0` adds an optional remote-download timeout; this
  repository uses its local string parse and unparse paths. The package does
  not publish a provenance attestation.
- Verified Oxfmt and Oxlint maintainer, repository, signature, and SLSA
  provenance continuity. Their platform bindings remain exact-versioned to
  the corresponding package release.
- The pre-update full and production Bun audits reported no vulnerabilities,
  and Bun reported no untrusted dependency lifecycle scripts.

## Changes

- Updated the runtime dependency caret ranges and exact Oxc development-tool
  pins in `package.json`, with exact reviewed resolutions in `bun.lock`.
- Updated the public Codex SDK baseline in `README.md` and
  `docs/guides/cli-action-tool-integration-guide.md` to
  `v0.1.8-canary.1` / `0.150.1`.
- Reworded the active execution-configuration research to identify SDK
  `0.149.1` as its research baseline instead of a moving current dependency.
- Preserved package version `0.1.8-canary.1`, Node.js engine `>=22.23.0`, and
  `@types/node` `25.9.5`.

## Validation

- Frozen installation passed with Bun `1.4.0`; 171 installs across 287 packages
  required no changes.
- The updated-lock full and production audits reported no vulnerabilities across
  276 and 138 checked packages respectively, and Bun reported no untrusted
  dependency lifecycle scripts.
- Native `tsc --noEmit` passed with the unchanged Node-only ambient-type
  boundary.
- 21 direct Codex adapter tests and 9 PapaParse-backed data conversion tests
  passed across 5 files with 0 failures.
- Oxlint `1.80.0` passed without diagnostics.
- Oxfmt `0.65.0` checked 1,002 files without formatting changes.
- The Node 22 build passed with tsdown `0.22.14` and TypeScript `7.0.2`
  declaration generation.
- The SDK import smoke passed, the bundled executable reported
  `codex-cli 0.150.1`, CJS and ESM library import smokes passed, and the built
  CLI reported `0.1.8-canary.1`.
- The full suite passed with 2,623 tests across 355 files and 0 failures.
- `git diff --check` passed.
- Final `bun outdated` showed no remaining reviewed candidate; the only actual
  version advance shown is the intentionally deferred `@types/node@26.3.0`
  major.

## Notes

- Canary releases do not receive a manually authored file under `CHANGELOGS/`.
- Moving to Node 26 declarations remains a separate runtime/type-baseline
  decision.
- The bundled Codex CLI version smoke emitted a restricted-environment warning
  while attempting to create PATH aliases, then reported `codex-cli 0.150.1`
  successfully.

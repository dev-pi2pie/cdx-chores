### SQL Migration Matrix

| Expression or behavior | 1.5.6 → 2.0.0 | Verified migration guidance |
| --- | --- | --- |
| `'abc' ~ 'b'` | `false` → `true` | Use `regexp_full_match('abc', 'b')` for full matching, or `regexp_matches` for partial matching. |
| `list_transform([1,2], x -> x + 1)` | Accepted → rejected | `list_transform([1,2], lambda x: x + 1)` returns `[2,3]` on both. |
| `2 * 3!` | `720` → `12` | `(2 * 3)!` preserves `720`. |
| `X'AB'`, `B'101'` types | `VARCHAR` → `BLOB` / `BIT` | Use ordinary quoted strings when text is intended. |
| Untyped `NULL` in CTAS | `INTEGER` → `NULL`, rejecting non-null inserts | Cast to the intended type. `NULL::VARCHAR` accepts later text inserts. |
| `1 // 0`, `1 % 0` | `NULL` → error | `TRY(...)` preserves null results. Floating division still returns infinity. |
| Binder error inside a transaction | Transaction usable → aborted | Roll back before the next query. Recovery is verified. |
| `preserve_identifier_case` | Boolean → string setting values | Boolean aliases still work, mapping to `preserve_case` / `lowercase`. |

These differences affect submitted SQL and migration guidance. Application-generated SQL does not use the changed operators. Do not rewrite arbitrary user SQL or enable blanket legacy settings.

`VARIANT` scalar/nested reading and prepared insertion pass. Direct logical-type construction is rejected by the candidate, as tracked in [upstream issue 524](https://github.com/duckdb/duckdb-node-neo/issues/524). Capture schema metadata before closing results. New type/function-registration coverage is limited to the tested paths. Generated SQL has no `MERGE`, S3 URL settings, or removed logging/profiling calls. Other submitted SQL should follow the [full migration guide](https://duckdb.org/docs/2.0/operations_manual/migration).

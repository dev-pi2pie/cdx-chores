## Goal and Scope

Prepare `0.2.2-canary.2` by refreshing dependencies and migrating supported DuckDB workflows to DuckDB 2. Verify compatibility and document behavior changes. Phases 1–3 are complete. Phase 4 has not started.

Keep the package version, already `0.2.2-canary.2`, unchanged. Publishing and tagging are outside this plan.

## Settled Decisions

- Phase 1 reviews the twelve non-DuckDB targets below, including `@openai/codex-sdk@0.167.0`. Unresolved SDK security or compatibility issues prevent Phase 1 completion.
- Retain `@duckdb/node-api@1.5.6-r.2` during Phase 1. Phase 2 defines migration requirements. Phase 3 implements and verifies them. Resolve compatibility blockers before advancing. The migration is required for plan closeout.
- Preserve Node.js `>=22.23.0`, Node-only compiler ambient types, Node 22 build targets, lazy SDK loading, and existing exact-pin/range conventions. Bun remains development tooling.
- Use the [single job record](jobs/2026-11-06-v0.2.2-canary.2-dependency-refresh.md) for all four phases. This plan defines steps and acceptance criteria. The job record captures versions, findings, decisions, verification, and reviews.
- Review SDK/CLI, runtime, and tooling updates as separate batches. Explicitly accept or defer each candidate based on evidence, including patch/minor updates.
